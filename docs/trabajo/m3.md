# M3 — Dashboard con números verdaderos

**Patrón:** corrección de bug (sin patrón); consultas que respetan el estado de anulación.

## Problema (código antes)

`DashboardServiceImpl.obtenerEstadisticasGenerales()`:

```java
long creditos = creditoRepository.count();
BigDecimal totalFinanciado = creditoRepository.sumarImporteCuotaTotal();
BigDecimal totalCobrado = cobranzaRepository.sumarImporteTotal();
```

```java
@Query("SELECT COALESCE(SUM(c.importeCuota), 0) FROM Credito c")
@Query("SELECT COALESCE(SUM(c.importe), 0) FROM Cobranza c")
```

## Solución (código después)

```java
List<Credito> todos = creditoRepository.buscarTodosConCuotas();
cuotaRepository.buscarTodasConCobranzas();
long creditos = todos.stream().filter(credito -> credito.estado() == EstadoCredito.VIGENTE).count();
BigDecimal totalFinanciado = creditoRepository.sumarDeudaOriginalVigente();
BigDecimal totalCobrado = cobranzaRepository.sumarImporteVigente();
```

```java
@Query("SELECT COALESCE(SUM(c.deudaOriginal), 0) FROM Credito c WHERE c.anulado = false")
@Query("SELECT COALESCE(SUM(c.importe), 0) FROM Cobranza c WHERE c.anulada = false")
```

## Por qué

"Financiado" sumaba `importeCuota` (el valor de una cuota, no lo prestado), "Créditos Activos" contaba anulados y "cobrado" sumaba cobranzas anuladas. Cierra TPO-003 y la parte de anulados de B-04 (V0): los cuatro números del dashboard del supervisor ahora reflejan solo lo vigente. "Créditos Activos" usa la misma regla que `Credito.estado()` (ni anulado ni cancelado), así la vigencia vive en un solo lugar (Information Expert). Cargar todos los créditos en memoria no pesa para el volumen del TPO.
