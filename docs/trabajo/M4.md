# M4 — Permisos de anulación aplicados en el backend

## Patrón

MVC (validación por capa) + Information Expert: la vista oculta el botón, el controlador identifica al usuario, el modelo (`Permisos`) decide.

## Problema

`CreditoController.anularCredito` y `CreditoServiceImpl.anularCredito` (igual en `CobranzaController` / `CobranzaServiceImpl.anularCobranza`), en V2:

```java
@DeleteMapping("/anular/{id}")
public ResponseEntity<Void> anularCredito(@PathVariable Long id) {
    creditoService.anularCredito(id);
    return ResponseEntity.noContent().build();
}

public void anularCredito(Long id) {
    Credito credito = buscarCredito(id);

    credito.anular(cobranzaRepository.existeCobranzaDelCredito(id));
    creditoRepository.save(credito);
}
```

El servicio no sabe quién anula. Los permisos que asigna el supervisor se guardan pero nadie los consulta: solo el front oculta el botón, y cualquier operador anula por API.

## Solución

```java
@DeleteMapping("/anular/{id}")
public ResponseEntity<Void> anularCredito(@PathVariable Long id, @AuthenticationPrincipal UsuarioDetails principal) {
    creditoService.anularCredito(id, principal.getUsuario());
    return ResponseEntity.noContent().build();
}

public void anularCredito(Long id, IUsuario usuario) {
    if (!usuario.getPermisos().permiteAnularCredito()) {
        throw new AccessDeniedException("El usuario no tiene permiso para anular creditos");
    }

    Credito credito = buscarCredito(id);

    credito.anular(cobranzaRepository.existeCobranzaDelCredito(id));
    creditoRepository.save(credito);
}
```

`IPermisos` / `Permisos` suman `permiteAnularCredito()` y `permiteAnularCobranza()`; `UsuarioDetails` expone el `IUsuario` que adapta (`getUsuario()`). La `AccessDeniedException` ya la traduce `GlobalExceptionHandler` a 403.

## Por qué

Cierra TPO-007 (B-01 de V0): el CU19 "Asignar permisos de anulación" era decorativo. La regla de negocio vivía solo en la vista (H7); en MVC la vista oculta, pero quien valida es el controlador/modelo. La pregunta "¿puede anular?" la contesta `Permisos`, que tiene la información.

## Consecuencias

Gana: el permiso se respeta aunque se llame a la API sin el front, y la regla queda en un único lugar del modelo. Cuesta: las firmas de `anularCredito` / `anularCobranza` ahora dependen del usuario autenticado, y el servicio queda acoplado a `IUsuario`.
