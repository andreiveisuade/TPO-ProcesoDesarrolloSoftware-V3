# M5 — Handlers HTTP específicos

## Patrón
MVC: el controlador (capa de traducción) convierte errores del modelo y de la infraestructura en respuestas HTTP con el código correcto.

## Problema
`GlobalExceptionHandler` solo conocía tres excepciones; el resto caía en `handleGeneral` y respondía 500.

```java
@ExceptionHandler(Exception.class)
public ResponseEntity<ErrorResponse> handleGeneral(Exception ex) {
    return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(
        new ErrorResponse(500, "Error interno", List.of(ex.getMessage()), LocalDateTime.now())
    );
}
```

Login incorrecto, ruta inexistente, acceso denegado y método no soportado daban 500.

## Solución
Cuatro handlers nuevos en `GlobalExceptionHandler`, con el mismo `ErrorResponse`:

```java
@ExceptionHandler(AuthenticationException.class)            // 401
public ResponseEntity<ErrorResponse> handleAuth(AuthenticationException ex) { ... }
@ExceptionHandler(AccessDeniedException.class)              // 403
public ResponseEntity<ErrorResponse> handleDenied(AccessDeniedException ex) { ... }
@ExceptionHandler(NoResourceFoundException.class)           // 404
public ResponseEntity<ErrorResponse> handleNoResource(NoResourceFoundException ex) { ... }
@ExceptionHandler(HttpRequestMethodNotSupportedException.class) // 405
public ResponseEntity<ErrorResponse> handleMetodo(HttpRequestMethodNotSupportedException ex) { ... }
```

## Por qué
Cierra TPO-001 y TPO-002 (H9): un error del cliente ya no se reporta como falla del servidor, y el front puede distinguir 401/403/404/405 de un 500 real.
