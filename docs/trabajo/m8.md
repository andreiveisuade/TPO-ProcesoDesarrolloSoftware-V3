# M8 — EstadoCredito + Credito como agregado de sus cuotas

## Patrón

Information Expert y Creator (GRASP): el crédito crea sus cuotas y las conoce, así que es quien responde su estado, su saldo y si puede anularse. Absorbe M2.

## Problema

El estado del crédito era un boolean `anulado`: no existía "cancelado" ni saldo (H1, H2). Para anular, el servicio le contaba al crédito si tenía cobranzas, y lo hacía con una consulta que contaba también las cobranzas anuladas: un crédito cuya única cobranza fue anulada no se podía anular (TPO-002 / M2).

```java
// v2: model/Credito.java
public void anular(boolean tieneCobranzas) {
    if (tieneCobranzas) {
        throw new BusinessException(
            "No se puede anular el crédito " + id + " porque tiene cobranzas registradas."
        );
    }
    this.anulado = true;
}

// v2: service/impl/CreditoServiceImpl.java
public void anularCredito(Long id) {
    Credito credito = buscarCredito(id);

    credito.anular(cobranzaRepository.existeCobranzaDelCredito(id));
    creditoRepository.save(credito);
}

// v2: repository/CobranzaRepository.java
@Query("SELECT COUNT(c) > 0 FROM Cobranza c WHERE c.cuota.credito.id = :idCredito")
boolean existeCobranzaDelCredito(@Param("idCredito") Long idCredito);
```

## Solución

```java
// model/EstadoCredito.java
public enum EstadoCredito { VIGENTE, CANCELADO, ANULADO }

// model/Credito.java
@Getter(AccessLevel.NONE)
@OneToMany(mappedBy = "credito", fetch = FetchType.LAZY)
@OrderBy("numero")
private List<Cuota> cuotas = new ArrayList<>();

public EstadoCredito estado() {
    if (anulado) {
        return EstadoCredito.ANULADO;
    }
    return estaCancelado() ? EstadoCredito.CANCELADO : EstadoCredito.VIGENTE;
}

public BigDecimal saldo() {
    if (anulado) {
        return BigDecimal.ZERO;
    }
    return cuotas.stream()
        .filter(cuota -> !cuota.estaPagada())
        .map(Cuota::getImporte)
        .reduce(BigDecimal.ZERO, BigDecimal::add);
}

public boolean estaCancelado() {
    return !cuotas.isEmpty() && cuotas.stream().allMatch(Cuota::estaPagada);
}

public boolean tieneCobranzas() {
    return cuotas.stream().anyMatch(Cuota::estaPagada);   // estaPagada ignora anuladas
}

public boolean puedeAnularse() {
    return !anulado && !tieneCobranzas();
}

public void anular() {
    if (anulado) {
        throw new BusinessException("El crédito " + id + " ya está anulado.");
    }
    if (tieneCobranzas()) {
        throw new BusinessException(
            "No se puede anular el crédito " + id + " porque tiene cobranzas registradas."
        );
    }
    this.anulado = true;
}

// service/impl/CreditoServiceImpl.java
@Transactional
public void anularCredito(Long id, IUsuario usuario) {
    if (!usuario.getPermisos().permiteAnularCredito()) {
        throw new AccessDeniedException("El usuario no tiene permiso para anular creditos");
    }
    Credito credito = buscarCredito(id);
    credito.anular();
    creditoRepository.save(credito);
}

private Credito buscarCredito(Long id) {
    Credito credito = creditoRepository.buscarConCuotas(id)       // JOIN FETCH cliente + cuotas
        .orElseThrow(() -> new ResourceNotFoundException("Crédito", "id", id));
    cuotaRepository.buscarPorCredito(id);                          // JOIN FETCH cobranzas, mismo contexto
    return credito;
}
```

`CreditoResponse` suma `estado` y `saldo`; `Creditos.jsx` muestra el saldo y el estado. `listarPorCliente` pasa de N+1 (una consulta de cuotas por crédito) a dos consultas fijas. Se respetan M1 (`Cuota` sigue rechazando el cobro con `credito.isAnulado()`), M4 y M9.

## Por qué

Cierra H1 (estado como boolean), H2 (el sistema no sabía cuánto debe un crédito) y TPO-002 / M2: la regla "con cobranzas no se anula" ahora usa `Cuota.estaPagada()`, que ya ignoraba las cobranzas anuladas. El servicio deja de consultar al repositorio para pasarle un boolean al crédito: la decisión vuelve al experto.

## Consecuencias

Gana: estado y saldo calculados en un solo lugar, sin columna extra ni migración (`anulado` sigue siendo el dato persistido). Cuesta: el crédito necesita sus cuotas y cobranzas cargadas, así que el servicio las trae en dos consultas con `JOIN FETCH` dentro de una transacción (dos bags en una sola consulta tiran `MultipleBagFetchException`); quien cargue un `Credito` por otro camino y llame a `saldo()` fuera de transacción tendría `LazyInitializationException`.
