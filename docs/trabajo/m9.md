# M9 — Strategy del cálculo de cuota

**Patrón:** Strategy (GoF, comportamiento).

| Rol | Clase |
|---|---|
| Context | `model/Credito` (guarda `tipoPlan` y delega en `totalADevolver()` y en el constructor) |
| Strategy | `model/interfaces/CalculoDeCuota` (`importeCuota`, `totalADevolver`) |
| ConcreteStrategies | `model/plan/InteresSimple`, `model/plan/SistemaFrances` |
| Selección | `model/TipoPlan` (enum persistido); lo elige quien otorga el crédito vía `CreditoRequest.tipoPlan` |

**Revierte una decisión anterior:** el 15/09 (V2) se descartó el sistema francés y `Credito` justificaba interés simple porque "no se modela amortización". V3 reabre esa decisión: el francés entra como segunda estrategia real, así el patrón no queda con una sola implementación.

## Problema (V2, `Credito`)

El algoritmo estaba cableado en la entidad; agregar otro sistema obligaba a meter un `if` por tipo dentro de `Credito`.

```java
public BigDecimal totalADevolver() {
    BigDecimal coeficiente = BigDecimal.ONE.add(tasaInteres.divide(CIEN, 4, RoundingMode.HALF_UP));
    return deudaOriginal.multiply(coeficiente).setScale(DECIMALES, RoundingMode.HALF_UP);
}

private BigDecimal calcularImporteCuota() {
    return totalADevolver().divide(
        BigDecimal.valueOf(cantidadCuotas), DECIMALES, RoundingMode.HALF_UP
    );
}
```

## Solución (V3)

```java
// Credito (Context)
this.importeCuota = tipoPlan.calculo().importeCuota(deudaOriginal, tasaInteres, cantidadCuotas);

public BigDecimal totalADevolver() {
    return tipoPlan.calculo().totalADevolver(deudaOriginal, tasaInteres, cantidadCuotas);
}

// Strategy
public interface CalculoDeCuota {
    BigDecimal importeCuota(BigDecimal capital, BigDecimal tasaInteres, int cantidadCuotas);
    BigDecimal totalADevolver(BigDecimal capital, BigDecimal tasaInteres, int cantidadCuotas);
}

// ConcreteStrategy: SistemaFrances
public BigDecimal importeCuota(BigDecimal capital, BigDecimal tasaInteres, int cantidadCuotas) {
    BigDecimal i = tasaInteres.divide(new BigDecimal("100"), PRECISION);
    if (i.signum() == 0) {
        return capital.divide(BigDecimal.valueOf(cantidadCuotas), 2, RoundingMode.HALF_UP);
    }
    BigDecimal descuento = BigDecimal.ONE.subtract(
        BigDecimal.ONE.divide(BigDecimal.ONE.add(i).pow(cantidadCuotas, PRECISION), PRECISION));
    return capital.multiply(i).divide(descuento, 2, RoundingMode.HALF_UP);
}
```

`InteresSimple` conserva la fórmula de V2 sin cambios. `TipoPlan` (columna `tipo_plan`, default `INTERES_SIMPLE` para los créditos ya existentes) mapea cada valor a su estrategia. El front suma un `<select>` con los dos planes.

## Por qué

El cálculo del plan es "la misma acción con distintos algoritmos": el caso típico de Strategy. En V2 el sistema solo sabía otorgar a interés simple fijo sobre el total, y un plan con tasa mensual sobre saldo (francés, el habitual en préstamos) no era expresable. Ahora `Credito` no conoce ninguna fórmula: solo delega.

## Consecuencias

- Gana: un sistema nuevo (alemán, etc.) es una clase más + un valor del enum, sin tocar `Credito` (OCP). Cada fórmula se testea aislada.
- Cuesta: la tasa cambia de significado según el plan (% total en simple, % mensual en francés) y hay que decirlo en la UI; una columna más en `creditos`. La cuota sigue sin descomponerse en capital e interés: el francés define el importe, no la amortización.
